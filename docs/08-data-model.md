# Loomora: Data Model and Rules (A6, v1.0)

Database: PostgreSQL (Neon). All primary keys are **UUIDs generated by the client or server**, so guest data can move into an account without id clashes. All timestamps are stored in UTC. "Today" is always computed in the **user's own time zone** (users.timezone, an IANA name such as Asia/Phnom_Penh).

## Tables
**users**: id, name, email (unique), password (nullable for Google users), google_id (nullable, unique), email_verified_at, timezone, goal (be_consistent | manage_time | finish_tasks | other, nullable), heard_from (text, nullable), survey_done (bool), current_streak, longest_streak, last_streak_date, created_at, updated_at.

**todos**: id, user_id, title (max 200), category (study | work | health | life | rest | other), due_date (date, nullable), done_at (timestamp, nullable), created_at, updated_at.
R2 adds: notes, priority, parent_id (subtasks), repeat_rule (jsonb), remind_at.

**schedule_items**: id, user_id, title, category, start_time (time), end_time (time), days (smallint[] of 0 to 6, 0 = Monday), starts_on (date), ends_on (date, nullable), created_at, updated_at.

**schedule_exceptions**: id, schedule_item_id, date, type (skip | override), title (nullable), start_time (nullable), end_time (nullable). Unique (schedule_item_id, date).

**schedule_checkins**: id, schedule_item_id, date, done_at. Unique (schedule_item_id, date).

**feedback**: id, user_id (nullable), message, created_at.

Laravel Sanctum adds personal_access_tokens. A password_reset_tokens table is also needed.

## Business rules
1. **Today list** = to-dos with due_date = today, to-dos with no due date that are not done, and Overdue to-dos. Items with due_date in the future are hidden until their day.
2. **Overdue** is computed, not stored: due_date < today (user time zone) and done_at is null. It carries over automatically, with no scheduled job. Overdue items older than 30 days still show but are marked "Old".
3. **To-do default due date** is today when created from the Today screen.
4. **Schedule occurrence on a date D**: the item occurs if D is on or after starts_on, on or before ends_on (if set), and weekday(D) is in days. Then apply exceptions: skip removes it, override replaces title or times for that date only.
5. **"Only today"** edit creates an exception (override) for that date. **"All repeats"** edits the schedule_item itself. **Delete "only today"** creates a skip exception. **Delete all** removes the item and its exceptions and check-ins.
6. **Now / Next**: Now is the occurrence whose start <= current local time < end. Next is the first occurrence starting later today. If none, Now shows "Free" and Next shows "Nothing more today".
7. **Check-off**: a to-do is done when done_at is set (toggle clears it). A schedule occurrence is done when a schedule_checkins row exists for that date.
8. **Streak**: a local day counts if at least 1 to-do or schedule occurrence was checked off that day. A day with nothing planned (no to-dos due and no schedule occurrences) is skipped and never breaks the streak. A planned day with zero check-offs breaks it, but today is never judged until it ends. The server stores current_streak, longest_streak and last_streak_date and recomputes them lazily on check-off and on app open.
9. **Guest to account migration**: the client sends all guest to-dos, schedule items, exceptions and check-ins in one import call. Rows keep their client UUIDs. Import is idempotent (re-sending the same payload creates no duplicates) and runs in one database transaction. If it fails, nothing is written and the guest data stays on the device. After success the client clears local guest data.
10. **Delete account** removes the user and all their rows immediately (cascade).
11. **Validation**: title 1 to 200 characters; start_time < end_time; days not empty; at most 500 to-dos and 100 schedule items per user (R1 limits).
12. **Categories** are a fixed set of 6 (string enum), not a table.
